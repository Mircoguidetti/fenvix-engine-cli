# Channels to cover later

The closing rule (DECISIONS 2026-11-21, founder): *"A channel where the engine answers NOT PROVEN is not a
defect: it goes on a list of channels to cover later, and each one covered raises the share of tests that can be
skipped or spread across cores."* This file is that list, and it is generated, not remembered:
`python3 harness/provable_scan.py` produces it from the accounting table itself
(`crates/detpy-core/src/provable.rs`).

**How to read it.** A name here is a callable the table refuses, so a test that reaches it is NOT PROVEN and is
rerun instead of skipped or spread. That is the rule working, not a bug. What the list is for is priority: a
refusal an ORDINARY test reaches is worth covering (that is how `_thread.lock` and `posix.register_at_fork` were
found, after they had already cost 297 of 297 tests on the smoke project); `posix.setresuid` is not.

**The shape to watch.** The `_thread.lock` red was a TYPE whose methods the table listed and whose construction
it did not — `threading.Lock` IS the class `_thread.lock`, so the sensor reported the type's name. The types are
listed first for that reason: each one is a place where the table may be answering for the operation and not for
the object.
