# db-copies-read: pre-registration

Written 2026-11-26, before any third-party read. Base revision of the 20: `85b36b2452df` (`85b36b2452dfdc375b1e4177dd64287120b06e6d`, branch `claude/db-serial-count`). Branch `claude/db-copies-read` from `origin/claude/release-1` at `ece09e1f502a1d7354e563226ec890046d196fc7`. Any later change is listed in REPORT.md under "Changes after PREREG" (file `CHANGES.md`) with its justification, before any result. A change after any table row exists is allowed only for a code bug (not a rule), with every affected row regenerated.

## 1. Decision line and outcomes (memo, quoted; not reopened)

"By 5 Dec 2026, if fewer than 5 of the 20 repositories show a public pain signal (a linked issue/PR/commit about slow tests or a failed or reverted parallel attempt) AND fewer than 5 have a free per-worker database option available but off, the idea goes back to the list after 22/12 with no design. If both lines hold, the next step is a design (/office-hours design doc, then /plan-eng-review) of 'per-lane database with proof' for the most common stack."

Three outcomes, printed by `lines.py` (the session decides nothing beyond printing):
- `CONTINUE TO DESIGN`: pain >= 5 AND free_off >= 5.
- `BACK TO LIST`: pain < 5 AND free_off < 5.
- `SPLIT (pain holds)` / `SPLIT (free_off holds)`: one count >= 5 and the other < 5. The memo does not cover it; it is reported as printed.
- `INCOMPLETE`: any row not read completely; no outcome is printed.

The denominator is always 20; a repository that cannot be read (404, 451, archived) counts as "no" for both lines and is listed first.

## 3. Route and caps (§1, §5)

Every third-party read runs in `.github/workflows/db-copies-read.yml` with `GITHUB_TOKEN` (GET only), triggered by a push that adds one request file `harness/db_copies_read/requests/<n>.json`. The workflow makes no commit; it uploads `results/` outputs as the artifact `db-copies-read-<n>` (30 days); the session downloads it (GitHub MCP `list_workflow_runs` → `list_workflow_run_artifacts` → `download_workflow_run_artifact` → `curl`), records the download host in `results/transport.log`, and commits it under the founder identity.

Client (`ghapi.py`, copied from `85b36b2452df` and changed): search guard on normalised paths (leading `https://api.github.com` and `/` stripped; `search/...` refused before sending); no `gh api` fallback; no sleep above 600 s (a longer wait checkpoints and exits 0, `paused`); at most 1 core request per 2 s; pause when the last observed core `X-RateLimit-Remaining` is below 20% of the last observed `X-RateLimit-Limit`; a 403/429 with `X-RateLimit-Remaining: 0` or a message containing "rate limit", "secondary rate limit" or "abuse" is a rate-limit response (wait per `Retry-After`/reset within 600 s, else checkpoint); any other 403 is a stop; 5xx and network errors are tried 3 times in all, then the field is `incomplete`; every counter counts HTTP attempts, retries included.

Per repository, at most: `GET /repos/{o}/{r}` 1; `/contributors?per_page=1&anon=1` 1; `/git/trees/{default_branch}?recursive=1` 1; `/contents/{path}` 15 (directory listings of the root and the step's `wd` when the tree is truncated count inside the 15); `/issues?state=all&since=2024-01-01T00:00:00Z&per_page=100` 10 pages; `/commits?since=2024-01-01T00:00:00Z&per_page=100` 10 pages; `/commits?path=<f>&since=...&per_page=100` 6 (1 page each); `/commits/{sha}` 40; `/issues/{n}/comments?per_page=100` 15; `/pulls/{n}/files?per_page=100` 15. Total 114; 2,280 for 20.

Issues disabled (`has_issues` false or `/issues` answers 410): `/pulls?state=all&sort=created&direction=desc&per_page=100` instead (same 10-page cap; paging stops once a page ends before 2024-01-01), `issues: disabled`; a 410 is never a stop. A 403 from `/contributors` saying the list is too large gives contributor count `unknown` (context only), not a stop.

The 1,500 checkpoint: when cumulative attempts reach 1,500 the job finishes the current repository, checkpoints and exits 0 (`checkpoint-1500`); the session commits `report.py --partial` and continues (never past 2,280; request field `bound`) only on the coordinator's answer. The job also stops at 2,280.

Checkpoint continuity (gate M1): the reference is the last run of `db-copies-read.yml` with conclusion `success` that uploaded an artifact. The job refuses (exit 1, `stale checkpoint`) when the checkout's `results/checkpoint.json` `run_id` is not that run, or when a checkpoint exists without such a run, or none exists with one. Every successful run (the docs run included) carries the previous progress forward and adds its own. Progress is kept per repository and per stage; a stage that is `incomplete` is re-read by the next request naming the repository.

Stops (report to the coordinator and wait): the derivation not matching; an access 403 on a public repository; the artifact start check failing or an artifact the session cannot download (including a download host other than the allowed `productionresultssa32.blob.core.windows.net`); a §6 contradiction of §4; the 1,500 checkpoint. Deadline: REPORT.md (`INCOMPLETE` allowed) committed, pushed and reported by 4 Dec 2026 23:59 UTC.

## 4. Fields per repository (§2)

All values come from stored responses under `results/raw/<owner>__<repo>/<stage>.json.gz` (stages `meta`, `contributors`, `tree`, `files`, `issues`, `commits`, `pathcommits`, `diffs`, `comments`, `pullfiles`; each holds the GET path, status, the headers `link`, `date`, `x-ratelimit-*`, and the JSON body as returned; no body field is trimmed). `build.py` turns them into `results/table.jsonl` offline.

- **a. Stack and runner.** The runner is `timing.kind` and its line (§2 above). Files fetched (at most 15): first pass (at most 12): the workflow file, the runner line's `src`, at the root and the step's `wd`: `pytest.ini`, `pyproject.toml`, `setup.cfg`, `tox.ini`, `conftest.py`, `jest.config.*`, `.mocharc*`, `vitest.config.*`, then dependency files `pyproject.toml`, `Pipfile`, `package.json`, `go.mod`, `requirements*.txt` (root and `wd` only). Second pass: `conftest.py` in the first test directory named in the runner line (first non-flag argument that is a directory in the tree, or the parent of a file argument) or else in the first `testpaths` entry; then, for a Django project, `manage.py` (in `wd`, the root, else the shallowest in the tree) and the settings module named in `DJANGO_SETTINGS_MODULE` (`a/b/settings.py` or `a/b/settings/__init__.py`, relative to `wd`, the root or the `manage.py` directory). Files beyond 15 are listed as not fetched. ORM/driver names recorded from dependency files: SQLAlchemy, Django, psycopg, psycopg2, asyncpg, Prisma (`prisma` or `@prisma/client`), TypeORM, Knex, Sequelize, drizzle-orm, pgx (`jackc/pgx`), gorm, sqlx; Testcontainers = `testcontainers` in any dependency file.
  - **Django project:** `django` (any case, as a package name not followed by `-` or a word character, so `pytest-django` alone does not count) in a dependency file, OR `DJANGO_SETTINGS_MODULE` set in the workflow, `pytest.ini`, `pyproject.toml` or `setup.cfg`, OR a `manage.py` file in the tree.
- **b. Free per-worker option.** `level` (§6 below) and `state`: `on`, `off`, `n/a` (level `none`), or `unknown` (Django: settings module not fetched, or settings mention `parallel` or `TEST_RUNNER`; or the runner line not found in the stored file). `off` carries the evidence: file path, line number and line text of the runner line in its stored file (the line holding the longest whitespace-normalised token prefix of the runner line). For pytest, `off` also needs no parallel `-n`/`--numprocesses` token in any `addopts` line (and its continuation lines) of `pytest.ini`, `pyproject.toml`, `setup.cfg`, `tox.ini`. `on` is recorded with evidence and reported as a db-serial-count rule miss, never counted as off. Per-test isolation lines (`TestCase`, `TransactionTestCase`, `django_db`, `rollback`, `begin_nested`, `transaction.atomic`, `create_database`, `drop_database`) in fetched `conftest.py` files and the settings module are recorded as notes and not counted.
- **c. Pain signals.** Every matched item as `{kind, url, date, author_type, quote, rules, counted}` in `results/items.jsonl`; `pain = yes` when at least one counted item passes the hand check and is not rejected by the coordinator's re-check.
- **d. Stated reason.** Comment lines (`#` or `//`) within 10 lines of the runner line in its stored file; or the text of a passed item that states why (marked in the hand check); else `none stated (runner default)` for reason `default-serial`, `none stated` otherwise.
- **e. Context (never used by a line).** Stars, forks, `created_at`, `pushed_at`, owner type, contributor count (from the `Link` header `rel="last"` page of the `per_page=1` call), open issues count, issues enabled, numbers of issues, pulls and commits read since 2024-01-01.

## 5. Pain signals (§3)

**Read set.** Issues and pulls through `/issues?state=all&since=2024-01-01T00:00:00Z` (pulls are items with a `pull_request` key, `merged_at` from it), at most 10 pages, newest first. Commits on the default branch through `/commits?since=...`, messages only, at most 10 pages. Diffs (`/commits/{sha}`) only for: commits whose message matches P1, P2-text or P3-text (newest first; commits excluded under "Does not count" are not queued), then commits listed by `/commits?path=<f>` (newest first) for the workflow file and the test-runner config files present among the fetched files (`pytest.ini`, `setup.cfg`, `tox.ini`, root `conftest.py`, `jest.config.*`, `.mocharc*`, `vitest.config.*`, the Django settings module; `pyproject.toml` only when it holds `[tool.pytest.ini_options]`), at most 6 files in that order; at most 40 diffs; when the cap is hit the field is `truncated` and REPORT gives how many of each kind were left out. "Matched by title/body" = a P1, P2-text or P3-text match on an issue or pull title+body (and not excluded). Comments are fetched for issues and pulls matched by title/body; pull files for pulls matched by title/body, the closed pulls with `merged_at` null that matched P2-text first, then the others; newest first within each group; at most 15 each. Truncated fields are listed; the window read is 2024-01-01 onward. The `since` listings are a fetch bound only; an item is excluded as "before 2024-01-01" when its `created_at` (issues, pulls, comments) or `commit.author.date` (commits) is before 2024-01-01T00:00:00Z (gate M5).

**Matching.** Case-insensitive. Word terms match whole words only (`\b` on both sides; for multi-word terms, the words joined by a single space or hyphen). Each term list is matched independently over the whole text; one span may satisfy terms of two lists (gate M4: `pytest-xdist` gives a parallel term and a test term). Text between triple backticks (an unclosed block runs to the end) is ignored for all text rules. Flag tokens match as literal tokens: a token starts at the line start or after whitespace, a quote, or one of `( [ { , =`, and ends at the line end or before whitespace, a quote, or one of `) ] } , ;` (the punctuation covers the config-key forms such as `maxWorkers: 1,`). Both the space and `=` forms are matched. Tokens in item text also count as parallel or database/serial terms.

- parallel: `-n <N>` / `-n=<N>` with N >= 2 or `auto` (lines containing `pytest`, `py.test` or `addopts` only), `--numprocesses <N>` / `--numprocesses=<N>` (N >= 2, `auto` or `logical`), `--parallel` / `--parallel <N>` / `--parallel=<N>` (`manage.py test` lines only), `parallelize(`, `--maxWorkers <N>` / `--maxWorkers=<N>` / `maxWorkers: <N>` with N >= 2 or a percentage, `-w <N>` / `-w=<N>` with N >= 2 (Jest lines), `-p <N>` / `-p=<N>` with N >= 2 (`go test` lines only), `--test-concurrency <N>` / `--test-concurrency=<N>` with N >= 2, `fileParallelism: true`, `--jobs <N>` with N >= 2 (mocha lines).
- serial: `-n 0` / `-n=0` (pytest only), `--runInBand`, `-i` (Jest lines), `--maxWorkers 1` / `--maxWorkers=1` / `maxWorkers: 1`, `-w 1` / `-w=1` (Jest lines), `-p 1` / `-p=1` (`go test` lines only; pytest's `-p` loads plugins and never matches), `--test-concurrency 1` / `--test-concurrency=1`, `fileParallelism: false`, `--no-file-parallelism`.

Term lists: **speed** `slow`, `slower`, `takes too long`, `too long`, `minutes`, `hours`, `timeout`, `timed out`, `speed up`, `faster`, `long-running`, `long running`; **test** `test`, `tests`, `testing`, `test suite`, `pytest`, `jest`, `mocha`, `vitest`, `go test`, `integration tests`; **database/serial** `database`, `db`, `postgres`, `postgresql`, `mysql`, `mariadb`, `mongodb`, `mongo`, `sqlite`, `fixture`, `fixtures`, `serial`, `sequential`, `sequentially`, `one at a time`, plus the serial flag tokens; **parallel** `parallel`, `parallelize`, `parallelise`, `parallelism`, `parallelization`, `parallelisation`, `xdist`, `pytest-xdist`, `workers`, `concurrency`, `concurrently`, plus the parallel flag tokens; **failure** `flaky`, `deadlock`, `race condition`, `conflict`, `duplicate key`, `already exists`, `unique constraint`, `locked`.

Rules:
- **P1 slow tests (counted):** a speed term AND a test term in the same item (title+body, commit message, or comment).
- **P1-db (second figure, not used by the decision):** a P1 item that also has a database/serial term.
- **P2 parallel attempt (reported apart, not counted on its own):** P2-diff: a pull (its fetched files) or commit (its fetched diff) whose patch, outside README/docs/`*.md`/`*.rst`/changelog files, adds a parallel flag token (net of the same token on removed lines of the same file) or adds `pytest-xdist` to a dependency file; OR P2-text: a pull title+body or commit message with a parallel term AND a test term.
- **P3 failed or reverted parallel attempt (counted):** a P2 item later reverted (a later commit whose message contains `revert` and the P2 commit's first 7 sha characters or the P2 title, or whose fetched diff removes a token the P2 item added) (`P3-revert`); or a P2 pull with `merged_at` null and state `closed` (`P3-closed`); or **P3-text:** an item with a failure term AND a database/serial term AND a parallel term.
- **P4 parallel abandoned (counted):** a commit or pull whose patch adds a serial flag token where the runner was parallel before: the token belongs to a default-parallel runner (`--runInBand`, `-i`, `-w 1`, `maxWorkers 1` for Jest/Vitest; `fileParallelism: false`, `--no-file-parallelism` for Vitest; `-p 1` for `go test`), or a parallel flag token is removed in the same patch.
- An open or merged P2 attempt that is not P3 or P4 is reported apart, not counted.

**Does not count** (`excluded_reason`): authors with `user.type == "Bot"`, a login ending `[bot]`, or `dependabot`, `renovate`, `github-actions` (`bot`); titles starting `Bump `, `chore(deps)` or `Update dependency` (`dependency-bump`, including a bump of pytest-xdist); titles starting `chore(release)`, `release:`, a version number, `changelog`, or naming release notes (`changelog-or-release`); items whose prose names `actions/cache`, Docker layer caching, dependency caching or lint/build speed and do not satisfy P1 (`ci-speed-not-tests`); items before 2024-01-01 (`before-2024`); README or docs files in patches (ignored). The hand check removes any other item a reader would not agree is about the team's slow tests.

**Quote:** the first prose line (code blocks removed, stripped, at most 300 characters) holding a term of the first text rule in the order P3-text, P1, P2-text; for items matched only through a patch, the added patch line holding the token; else the title.

**Session hand check (mandatory).** For every counted item and every P2 item the session reads the stored text and decides `pass` or `fail` with a one-line reason, in `results/handcheck.jsonl` as `{repo, url, rule, counted, decision, reason}`. `pass` means a reader would agree the item is about the team's slow tests, or about a parallel attempt that failed or was reverted (for P2 apart: a parallel attempt). Only `pass` items with `counted: true` enter the pain count. Then, for 3 repositories with `pain = no` chosen by `random.Random(20261126).sample(sorted(no_pain_repos), 3)`, the session reads every stored issue and pull title and lists any it judges a pain signal the rules missed (`results/rulemiss.json`): reported as "rule misses", never counted, never used to change a rule. Every item carries the API `html_url`.

**Independent re-check (coordinator).** Before REPORT is final, the session sends the coordinator every counted `pass` item (URL, rule, quote). The coordinator re-reads 5 of them (all if fewer than 5), chosen at random, and answers `keep` or `reject` per item; answers go to `results/recheck.jsonl`; a rejected item leaves the count. If 2 or more of the 5 are rejected, the session re-does its hand check on all counted items with the coordinator's reasons and reports again.

## 6. Free per-worker option: levels per stack (§4)

| Stack the repository uses | Level | Free option | "off" evidence |
|---|---|---|---|
| Django test runner (`manage.py test`) | `built-in` | `--parallel` clones the test database per worker | the timed command without `--parallel`, and no parallel default in settings or `TEST_RUNNER` |
| pytest on a Django project with BOTH `pytest-django` and `pytest-xdist` in dependencies | `plugin-installed` | pytest-xdist with pytest-django gives a database per worker | no `-n`/`--numprocesses` in the timed command or `addopts` |
| pytest on a Django project with `pytest-django` but no `pytest-xdist` | `plugin-partial` | needs xdist added | reported apart, NOT counted |
| pytest on a Django project without `pytest-django` | `plugin-not-installed` | needs the plugin | reported apart, NOT counted |
| pytest without a Django project (SQLAlchemy, raw drivers, other) | `none` | user code (worker-id database names, templates) | `n/a` |
| Go | `none` | user code; testcontainers-go is a building block | `n/a` |
| Node (Jest, Mocha, Vitest, node:test) with Prisma, TypeORM, Knex, Sequelize, Drizzle or raw drivers | `none` | user code (worker-id database or schema) | `n/a` |
| Any stack with Testcontainers in dependencies | adds `building-block` | a container per worker in user code | reported apart, NOT counted |
| Rails minitest; RSpec with `parallel_tests` (reference only: none of the 20 is Ruby) | `built-in`; `plugin-installed` | `parallelize(workers:)`; `parallel_tests` | kept for the desk survey; no tests |

`free_off = yes` only for level `built-in` or `plugin-installed` with `state = off`. A missing plugin or dependency (`plugin-partial`, `plugin-not-installed`) and a building block are not "free and off": switching them on needs a new dependency or new code; they are counted and reported apart. If the desk survey shows a level wrong, the session stops and reports before computing the lines.

## 7. Desk survey (§6)

`desk_survey.md`, one row per tool: Rails, Django, pytest-django (with pytest-xdist), Prisma, TypeORM, Knex, Testcontainers (Python, Node and Go modules), Sequelize, Drizzle, PostgreSQL template databases, PGlite. Columns: tool, per-worker database (`yes` / `plugin` / `no` / `building block`), how, official documentation URL, quote (at most 300 characters) from the fetched page, fetch date, status `VERIFIED` (quote found in the fetched page) or `UNVERIFIED` (with the HTTP status or error). The pages (`docs_urls.json`) are fetched by the workflow job (request `{"docs": true}`, plain GET, User-Agent `fenvix-research`), stored gzipped under `results/docs/`; `desk_check.py` checks each quote for exact presence in the stored page text (script/style removed, tags stripped, entities unescaped, whitespace collapsed). An `UNVERIFIED` row for Django or pytest-django blocks the lines.

## 8. Report

`report.py` prints REPORT.md from committed files only, with the sections of spec §7, and fails when a counted quote is not in the stored raw text, an "off" evidence line is not in its stored file, a `plugin-installed` row lacks `pytest-django` or `pytest-xdist` in a stored dependency file, or the per-stack summary does not sum to 20. `lines.py` computes the outcome from `table.jsonl`, `items.jsonl`, `handcheck.jsonl` and `recheck.jsonl`; REPORT copies its output verbatim.
