# P2 C4: the post-run hazard analysis

Phase B (`BREAKDOWN.md`, C4) found `hazards()` (`node/src/parallel.js`) the largest main-process cost outside the
lanes: 9.1 s self in codex-multi-auth's profile, 3.0 s in lerna-lite's, from a scan of every written path for each
listed directory.

## What changed

My C4 change (commit `488e20c`, an index of written paths by parent directory, identical results proven by
`node/test/p2-c4-hazards.test.js`) was overtaken by the merge of `claude/release-1` 519bf1a0 (`72d02913`):
parallel-proof-gaps rewrote `hazards()` with new hazard rules (recursive roots, shared services, the root directory)
and its own sorted index (`sortedIndex().under()`, binary search) for the listing lookup. By the coordinator's
instruction its hazard and proof rules win on any conflict, so `hazards()` at the head is release-1's verbatim (an empty
diff against release-1's function) and my C4 code is gone.

- Test deletion (approved by the founder, 2026-11-27): `node/test/p2-c4-hazards.test.js`. It compared `hazards()`
  with the 6e79a62 algorithm; release-1 changed the rules on purpose, so it failed 2/2 on the merge and had nothing
  left to test.

## Result differences

Identical output on lerna-lite and ironcurtain. On codex-multi-auth and drydock every hazard the 6e79a62 algorithm finds
is still found ("old only": none); the head adds `shared-service` hazards (codex-multi-auth 5, drydock 45, among them a
group of Docker watcher tests on port 80). That is release-1's rule (two files connecting to the same loopback port or
tcp address pair unless both found the address public); these markers were recorded by the baseline engine, which did
not record `pub`, so every such pair counts (the safe side). With the head engine recording `pub`, the count on a real
run can be lower. More hazards mean more files in the one-lane re-run, which costs time: that cost belongs to
release-1's correctness rule, not to C4, and shows in the Phase D re-measure.
