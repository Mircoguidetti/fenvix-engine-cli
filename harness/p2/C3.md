# P2 C3: --det-workers=N overrides a Vitest project's singleThread/singleFork (coordinator decision D3 = A)

Commit `17775df2` (`node/src/vitest/cli.js`; test `node/test/p2-c3-override.test.js`, 3 tests). An explicit
`--det-workers=N` (not Vitest's `--maxWorkers`, not the default worker count) turns off `singleFork` / `singleThread`
of the projects that set it, so each file runs in a fresh worker of its own, in N lanes; any other refusal reason still
keeps the run serial. Written to `meta.parallel.requested.override`, to the isolation line (header and summary) and on
stderr. Only agentlang in the pool sets it (`pool: 'forks', poolOptions.forks.singleFork: true`, "to prevent SQLite
database lock issues").

## Measure (agentlang, 3 rounds per engine, same boot b0517ae9)

`data/c3-before` (70a44716, just before C3) and `data/c3-after` (17775df2); `table.py compare` (`data/c3-after/COMPARE.md`):

| | E best median [cold] | PS/E | E/PP | S1/PS |
|---|---|---|---|---|
| before | 78.07 [79.07] | 0.87 | 3.03 | 1.17 |
| after | 75.65 [109.60] | 0.92 | 2.80 | 1.17 |

The override takes effect (every w2/w4 run: `override` set, 4 lanes planned). Round 1 runs 4 lanes in 29.3 s of lane
time, then finds 161 `read-write` hazards on one file, `logs/app-<date>.log` (the application's logger, written and read
by every test file), and re-runs 21 of the 25 files in one lane (109 s). From round 2 the plan state keeps those files
together: 22 of 25 in one lane (lanes 0/0/3/22, together 20), so the run is as serial as before. That is the hazard
rule working as designed on a genuinely shared file, not a C3 defect; making agentlang parallel needs a decision on such
log files (hazard rules, C1, parallel-proof-gaps), not this change.

Correctness: the fixed-epoch runs are w1 (`c3b` before; `c3a`, `c3ar` after), where the override does not apply (it
needs N > 1); outcomes 437 passed / 2 failed in all three, as in every earlier agentlang run.
